# wiley-agent Module Conventions

包定位、依赖方向、import 规则与路径解析约定见仓库根 `AGENTS.md`；本文件是 `wiley_agent` 包内各模块的详细约定。

## Factory（组装入口）

- `wiley_agent/factory.py` 是组装的唯一入口，两层：`bootstrap(session_id=None, *, config_path=None)` 一站式组装——`load_config` 构造 `AnthropicProvider` → 内置 `DEFAULT_TOOLS` → `load_debug_config` → `create_agent`（`mcp_config` 即同一 config.toml，`[anthropic]`/`[debug]`/`[[mcp.servers]]` 共用这一份文件），TUI 等宿主用它；`create_agent(session_id=None, *, provider, instruction=None, tools=None, prompt_providers=None, workspace=None, sessions_dir=None, debug_config=None, mcp_config=None)` 为可编程组装点，自定义 provider/工具/提示词组合时直接调用。session_id 传入则恢复会话、省略则自动生成 UUID；`debug_config` None 即关闭；`mcp_config` 为 MCP 配置文件路径，None 即不启用 MCP，传入时文件必须存在且合法，其中的 server 工具被自动转为 `Tool` 并入工具集；instruction 为系统提示词首段；tools 省略时无本地工具（仅配置的 MCP 工具可用）；prompt_providers 省略时使用 `default_prompt_providers(provider.model, workspace)`；sessions_dir 省略时写 CWD 的 `.agent_session/`。外部（含 TUI）一律经这两个入口创建 agent，不手工拼装 AgentService/SessionStore。

## 工具体系

- 工具体系在 `wiley_agent/tools/`：`base.py` 定义 `Tool` 契约（API schema + 本地执行器），内置工具每个一个子模块（现有 `bash.py`、`grep.py`、`read.py`、`edit.py`、`write.py`），在模块级定义 `Tool` 实例即可——`__init__.py` 自动扫描包内所有子模块收集全部 `Tool` 实例组成 `DEFAULT_TOOLS`（同名不同实例在导入期报错），新增内置工具不需要手工注册；不含 `Tool` 实例的共享辅助模块（如 `file_state.py`）可以并存，auto-scan 自然跳过。外部工具按同一契约编写后经 `create_agent(tools=...)` 注入。执行语义：工具执行失败以 `Error: ...` 字符串作为 tool_result 返回给模型（同时置 `is_error: true`；成功结果不带该字段），不中断流；`AgentService` 用 `asyncio.to_thread` 执行工具，执行器保持同步实现即可，允许阻塞（如 bash 命令）而不冻结事件循环。
- `bash` 工具（`wiley_agent/tools/bash.py`）参照 Anthropic bash tool 文档实现：进程级单例的持久 bash 会话（惰性启动、stderr 并入 stdout、`start_new_session` 独立进程组），用每次调用唯一的哨兵行捕获输出与退出码（非零退出在结果尾部附 `Exit code: N`）。`restart=true` 重建会话；命令超时（默认 120s，`_COMMAND_TIMEOUT_SECONDS`）或会话意外退出时 kill 整个进程组、下次调用惰性重建。输出截断：200 行 / 30000 字符；读取阶段另有 1MB 捕获上限（单次 readline 100KB），失控输出只丢弃不撑爆内存；子进程输出以 `errors="replace"` 解码，坏字节不会杀死读线程。审计：经 `logging`（`...tools.bash` logger）记录所有命令——执行前记命令（挂起也留痕）、完成后记退出码与输出前 200 字符、拒绝/超时记 warning。安全措施：命令执行前必须经 `validate_command` 显式校验——shlex 解析后按 `ALLOWED_COMMANDS` 白名单（而非黑名单）放行首个 token，并拒绝独立成词的 shell 运算符（`SHELL_OPERATORS`）及 `$`/反引号展开，解析失败即拒绝；校验不通过以 `Error: ...` 返回、不执行。扩展可用命令改 `ALLOWED_COMMANDS`。校验是绊线不是边界：仍无沙箱，放行的命令以当前用户权限执行。
- `grep` 工具（`wiley_agent/tools/grep.py`）仿 Claude Code 的 Grep tool，底层 shell out 到真实 ripgrep：`rg` 二进制来自 PyPI `ripgrep` 依赖（`sysconfig.get_path("scripts")` 定位、PATH 兜底），搜索语义（.gitignore、二进制跳过、glob/type 过滤、上下文行）即 rg 语义，正则为 Rust regex 方言。harness 层负责后处理：三种 `output_mode`（`files_with_matches` 默认、按 mtime 降序文件名 tiebreak；`content` 支持 `-A`/`-B`/`-C`/`context`、`-n` 行号；`count` 附总数 summary）、分页（`head_limit` 默认 250、0 不限、`offset` 跳过，仅实际截断时附 pagination 说明）、路径相对化。固定参数：`--hidden`、排除 VCS 目录 glob（含显式传入 `.git` 也搜不到）、`--max-columns 500`、`--with-filename`；总输出 30000 字符上限（同 bash）、30s 超时（超时抛错而非静默返回空，避免模型误判无匹配）；rg 退出码 2 且无 stdout 视为失败抛错，有 stdout 则采用部分结果。
- 文件三件套 `read`/`edit`/`write`（`wiley_agent/tools/read.py`/`edit.py`/`write.py`）仿 Claude Code 的 FileReadTool/FileEditTool/FileWriteTool，靠 `file_state.py` 的进程级读取状态注册表（同 bash 会话的单例模式）联动：`read` 记录所见内容/mtime/范围，`edit` 与 `write`（覆盖已有文件时）要求先读过且磁盘未变——mtime 变新但全量读过且内容一致则放行（容忍时间戳抖动），改写成功后刷新记录使连续编辑无需重读。`read`：cat -n 格式（行号+tab）、offset/limit 分页（默认上限 2000 行、截断时提示续读 offset）、单行截 2000 字符、全量读 256KB 上限（提示改用 offset/limit）、空文件/offset 越界返回 warning、拒绝二进制扩展名与阻塞设备文件（/dev/zero 等）、缺文件时附 CWD 与同名异扩展建议；同范围重读且文件未变返回 unchanged 存根省 token（edit/write 刷新的记录 offset=None，不参与去重）；默认 2000 行截断视为 partial view、不授权后续编辑（显式 offset/limit 的范围读可以）。`edit`：old_string 精确匹配且须唯一（多匹配报错并提示 `replace_all=true`）、old==new 报错、空 old_string 语义同参考实现（文件不存在=创建、存在且非空=报错）、CRLF 文件编辑后保留 CRLF。`write`：内容原样落盘不改行尾、自动建父目录。三者错误消息措辞对齐参考实现，便于模型自纠。

## AgentService 流事件

- `AgentService.stream` 的 `ChatStreamEvent` 事件类型为 `reasoning`/`answer`/`tool_call`/`tool_output`/`usage`/`done`：每个工具执行前发 `tool_call`（`tool_name`/`tool_call_id`/`tool_arguments`）、执行后发 `tool_output`（输出在 `text`，失败置 `tool_is_error=True`）；`usage` 事件除本轮/累计用量外带 `context_tokens`——取最后一次 API 请求的用量分量和（即当前上下文规模），不要用累计值的 `context_tokens` 当上下文（含工具的多轮请求会重复计缓存读）。`ConversationService.stream` 负责把工具事件写入会话记录（失败在 metadata 记 `is_error`）、把 `context_tokens` 存进答案记录 metadata；恢复用 `SessionStore.total_usage`（累计）与 `SessionStore.last_context_tokens`（最近上下文）。TUI 只消费流事件与 `SessionRecord`，不触碰工具层。

## MCP client

- MCP client 由 `wiley_agent/mcp.py` 的 `MCPClientManager` 实现：`create_agent(mcp_config=...)` 传入 TOML 配置文件路径（`bootstrap` 自动传 config.toml，可共用一个文件），内配 `[[mcp.servers]]`（`name` 唯一必填；`transport = "stdio"` 需 `command`/可选 `args`/`env`，`transport = "http"` 需 `url`/可选 `headers`）；`load_mcp_config` 解析——文件缺失/TOML 非法/字段非法抛 ConfigError，缺 `[mcp]` 段即无 server，`mcp_config=None` 即不启用 MCP；文件里的 server 由库自动连接并把其工具转为 `Tool` 并入工具集。SDK 全 async 且 session/transport 是 task 作用域 context manager，而 `Tool.execute` 是同步契约——manager 用专用后台线程跑独立 event loop，每个 server 连接活在该 loop 的一个长期任务里（整个 `async with` 栈在同一任务内进出），工具执行器经 `run_coroutine_threadsafe(...).result(120s)` 桥接，Tool 契约与 `AgentService` 均不改。工具以 `mcp__<server>__<tool>` 命名并入工具集（server 侧 `isError` → raise，由 `_execute_tool` 统一转 `Error: ...`）；stdio 的 `env` 与 SDK `get_default_environment()` 安全子集合并。生命周期：`create_agent` 解析 mcp_config、`start()` 阻塞至各 server 就绪或超时（连接失败/超时记 warning 跳过该 server，不阻断启动），组装后显式查重工具名（冲突抛 ConfigError）；`ConversationService` 提供 `close()`（factory 注入 closer），`wiley_tui/main.py` 的 finally 里调用释放连接。MCP 工具不经 `tools/` 的 auto-scan（那是包内静态内置工具的机制），由 manager 动态并入。测试见 `packages/wiley-agent/tests/test_mcp.py`，用 `sys.executable -c` 内联 FastMCP 脚本起真实 stdio server 做全链路验证。

## Debug 模式

- debug 模式由 `wiley_agent/debug.py` 的 `DebugRecorder` 实现：`create_agent` 收 `debug_config=DebugConfig(enabled=True)` 开启（None 即关闭）；`bootstrap` 经 `wiley_agent/config.py` 的 `load_debug_config` 从 config.toml `[debug]` 段解析后传入（文件/配置段缺失即关闭）。由 `create_agent` 装配、经 `AgentService(debug_recorder=...)` 注入。开启后把执行轨迹追加写会话文件同目录的 `<session_id>.debug.jsonl`（恢复会话时继续追加），记录类型：`session_start`（记 provider 类名与 model 标识）、`request`（每轮 harness 视角的请求输入：system/tools/messages，不含 api_key；厂商参数在 provider 实现内部、不经 harness）、`response_event`（逐条 provider 中立事件，刻意不聚合，用于定位"有请求无响应/流中断在哪"）、`response_end`（轮次完成标记，request 无配对 response_end 即该轮未完成）、`tool_call`/`tool_result`、`error`。挂钩只放在 `AgentService`（业务层），不改 provider 契约；debug 写入 flush 不 fsync（区别于 `SessionStore`）。

## System prompt 组装

- system prompt 统一由 `wiley_agent/prompt_template.py` 的 `build_prompt(instruction, providers)` 组装：instruction 为首段，其后按序拼接各 prompt provider 的段落。每个段落由 `BasePromptProvider` 子类提供（`ModelProvider`/`WorkspaceProvider`/`AgentMDProvider`/`SkillProvider`/`MemoryProvider`），`provide()` 返回完整 markdown 段落、返回 None 则跳过该段，且不得因来源缺失/不可读抛异常。新增段落时实现 `BasePromptProvider` 并加入 `default_prompt_providers`；注意与 LLM 侧 `wiley_agent/provider/base.py` 的 `BaseProvider` 是两套体系，不要混用。`SkillProvider`（扫描 `workspace/skills/*.md` 列清单）与 `MemoryProvider`（读 `workspace/MEMORY.md` 全文）目前为骨架，注入格式与路径约定后续迭代。不要在其他位置手工拼接系统提示词；工具的 schema/描述通过 API 请求的 `tools` 参数传递，不拼入 system prompt。

## LLM providers

- provider 契约与实现同在 `wiley_agent/provider/`：`base.py` 的 `BaseProvider` 是唯一契约，`stream_request(messages, *, system=None, tools=None) -> AsyncIterator[ProviderEvent]` 签名固定，只接收逐轮变化的会话状态；厂商参数（模型名、max_tokens、thinking、鉴权、endpoint、temperature 等）全部在实现类构造期注入，不出现在调用签名、也不经 `AgentService` 透传。可覆写 `model` property 暴露模型标识（供 system prompt 的 Model 段与 debug `session_start` 使用，默认空串即跳过）。契约与全部中立事件类型从 `wiley_agent` 包根导出。
- 契约语义（实现方义务，以 `BaseProvider` docstring 为准）：`messages` 使用 Anthropic 风格中立块 schema（assistant 的 thinking/redacted_thinking/text/tool_use 块、user 的 tool_result 块），非 Anthropic 后端由实现自行双向翻译；产出事件必须满足——`ToolCall` 按 index 流式拼装（首个事件带 tool_call_id/name，后续带 input_json 增量）、模型请求工具时 `UsageEvent.stop_reason` 必须映射为 `"tool_use"`（驱动 harness 工具循环，其余取值视为回合结束）、流内厂商错误发 `ErrorEvent`（harness 转 `ProviderError` 中止本轮）、传输/解码失败直接 raise `ProviderError`。usage 使用 `ProviderUsage`，不得依赖面向 TUI 的 `ChatUsage`；业务层不解析厂商原始事件字段，`AgentService` 不引入厂商 SDK。
- 内置实现：`wiley_agent/provider/anthropic.py` 的 `AnthropicProvider`（aiohttp 直连 Anthropic Messages API、SSE 解析、`from_event` 事件翻译，thinking 预算为 0 时不发 thinking 字段），构造参数由 `wiley_agent/config.py` 从 config.toml `[anthropic]` 段读取后经 `bootstrap` 传入，不从环境变量读取。新增厂商支持 = 库内新增 `provider/<vendor>.py` 实现契约（并视需要接入 `bootstrap`/config），或在外部实现 `BaseProvider` 子类注入 `create_agent(provider=...)`。
